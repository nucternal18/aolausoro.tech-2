# Design: P3.1a — Payload backend + admin + auth cutover

**Date:** 2026-09-08
**Branch:** `feature/refactor-portfolio` (continues from Phase 2, HEAD `9ac01c4`)
**Status:** Draft — awaiting review
**Depends on:** Phase 2 complete (`docs/superpowers/specs/2026-09-06-equilibrium-config-replication-design.md`)

## Context

`aolausoro.tech` is a personal portfolio + CMS, mid-migration from a
Clerk + Prisma + Redux + inversify-DI stack onto Payload CMS 3.86. Phase 2
(tooling / CI / deploy / docs replication from the `equilibrium` sibling
project) is done. Phase 3 finishes the migration, decomposed into four
sub-projects:

- **P3.1a (this spec)** — Payload backend loads + admin works + Clerk fully removed, replaced by Payload native auth.
- **P3.1b** — finish the layout-builder frontend + migrate existing data (old Atlas db → new Payload db, same cluster).
- **P3.2** — delete the old stack (`components/admin-route-components/`, `src/`, `prisma/`) + prune ~10 dead deps; get `tsc` + `build` green.
- **P3.3** — media Cloudinary → DO Spaces (+ SSRF fix); Sentry re-verify (kept); enable deploy + provision infra.

### Current state (verified 2026-09-08)

- `payload.config.ts` registers 8 collections: `Projects`, `Jobs`, `Messages`, `Wiki`, `Issues`, `Users`, `Media`, `Posts`. It **does not load** — `Posts` declares a `relationship` to `categories`, which is not a registered collection (`InvalidFieldRelationship`). This blocks `payload generate:types`, `getPayload()`, Payload init during `next build`, and the skipped `tests/int/api.int.spec.ts`.
- `slugField` **is** exported from `payload` 3.86 — the `Posts` import of it is fine, not a blocker.
- Auth today: `Users` collection has a **custom Payload auth strategy** (`clerk`) that calls `authenticateWithClerk` (`payload/access/clerk-auth.ts`), which reads a Clerk session (`@clerk/nextjs/server`), looks up / creates a Payload user by `clerkId`, and uses `CLERK_SECRET_KEY` to fetch Clerk profile data. `Users` has **no native email/password auth**.
- `proxy.ts` wraps `clerkMiddleware` to protect `/admin(.*)` — **but there is no `middleware.ts`**, so `proxy.ts` is not active. `/admin` is protected only by Payload's own auth check on the custom strategy.
- `routes.ts` is a dead NextAuth-style public/private route list — nothing imports it.
- Clerk touches 20 files; `svix` is used only by the Clerk webhook route.
- The 8 collections already use `src/access/*` helpers (`anyone`, `authenticated`, `authenticatedAndAdmin`, `authenticatedOrPublished`) — access work here is a review pass, not a rebuild.
- `nestedDocsPlugin` is configured in `plugins/index.ts` (currently pointed at template slugs, needs this repo's).
- `payload-totp@3.0.1` is installed (Phase 2) but not wired.

## Goals

1. `payload.config.ts` loads; `pnpm run generate:types` and `getPayload({ config })` succeed.
2. Payload `/admin` works end-to-end against a **fresh, empty db** — create first admin user, log in, CRUD every collection.
3. **Clerk entirely removed** — no `@clerk/*` import anywhere; `@clerk/nextjs`, `svix` dropped from `package.json`.
4. Payload **native email/password auth** on `Users`, with `payload-totp` **enforced** (`forceSetup: true`).
5. Explicit, reviewed access control on all 10 collections (the existing 8 + new `Categories` + `CVs`).
6. A `beforeDashboard` stat panel (4 cards).
7. `tests/int/api.int.spec.ts` un-skipped; new integration tests for auth + access; the two e2e helper/spec files the Phase 2 final review flagged as missing are created.
8. `tsc --noEmit` error count **drops** vs. the current 154 (Clerk + dead-route deletions).

## Non-goals

- **`pnpm run build` fully green** — `src/`, `components/admin-route-components/`, and Prisma remain until P3.2. P3.1a's build gate is "no *new* failure mode; tsc count down."
- **Data migration** — P3.1b. P3.1a runs against a fresh empty Payload db.
- **Finishing the layout-builder frontend** (`blocks/`, `heros/`, `RenderBlocks`, live-preview rendering) — P3.1b.
- **Media storage move to S3** — P3.3. Media stays on local `public/media`.
- **Removing `src/access/*`** — those are legitimate Payload access helpers; they stay (P3.2 may relocate them out of `src/` when `src/` is deleted, or keep the dir for just `access/`).

## Database

`DATABASE_URL` points at the db name **`portfolio`** in the existing Atlas
cluster (`mongodb+srv://<cluster>/portfolio`), replacing the old Prisma db
name. Payload creates fresh collections there. The old Prisma data is untouched
in its own db name and is P3.1b's migration source. Update `.env` (gitignored)
and document `portfolio` as the db name in `.env.example` + `docs/deployment-plan.md`.

## §1 — Categories collection + config load

### Files

- **Create** `payload/collections/Categories/index.ts`:

```ts
import type { CollectionConfig } from 'payload'
import { slugField } from 'payload'
import { anyone } from '@src/access/anyone'
import { authenticated } from '@src/access/authenticated'
import { authenticatedAndAdmin } from '@src/access/authenticated'

export const Categories: CollectionConfig<'categories'> = {
  slug: 'categories',
  access: {
    create: authenticated,
    delete: authenticatedAndAdmin,
    read: anyone,
    update: authenticated,
  },
  admin: { useAsTitle: 'title' },
  fields: [
    { name: 'title', type: 'text', required: true },
    ...slugField(),
  ],
}
```

(`slugField()` with no arg tracks `title` by default in 3.86 — verify against
the installed version; pass `{ trackingField: 'title' }` if the default differs.)

- **Create** `payload/collections/CVs/index.ts` — an upload-enabled collection for résumé/CV PDFs (dedicated collection per review decision — supports multiple labelled versions):

```ts
import type { CollectionConfig } from 'payload'
import { authenticated } from '@src/access/authenticated'
import { authenticatedAndAdmin } from '@src/access/authenticated'

export const CVs: CollectionConfig<'cvs'> = {
  slug: 'cvs',
  access: {
    create: authenticated,
    delete: authenticatedAndAdmin,
    read: authenticated, // private — owner-only
    update: authenticated,
  },
  admin: { useAsTitle: 'label', defaultColumns: ['label', 'user', 'updatedAt'] },
  upload: {
    mimeTypes: ['application/pdf'],
    staticDir: 'public/cvs', // local disk; S3 move is P3.3, same as Media
  },
  fields: [
    { name: 'label', type: 'text', required: true },
    { name: 'user', type: 'relationship', relationTo: 'users', required: true },
  ],
  timestamps: true,
}
```

- **Modify** `payload.config.ts` — add `Categories` and `CVs` to the `collections` array, **`Categories` before `Posts`** (Payload resolves relationships in array order):
  `collections: [Categories, Posts, Projects, Jobs, Messages, Wiki, Issues, CVs, Users, Media]`
- **Modify** `plugins/index.ts` — `nestedDocsPlugin({ collections: ['categories'], generateURL: (docs) => docs.reduce((url, doc) => \`${url}/${doc.slug}\`, '') })`. Remove any template slugs (`pages` etc.) that don't exist here.

### Verify

`pnpm run generate:types` exits 0; `payload-types.ts` regenerates with a
`Category` interface and `categories` on `Post`. `getPayload({ config })`
resolves in a REPL / the int test.

## §2 — Auth cutover: Clerk → Payload native

### `payload/collections/Users/index.ts`

Replace the whole `auth` block:

```ts
auth: {
  tokenExpiration: 60 * 60 * 8,   // 8h
  maxLoginAttempts: 5,
  lockTime: 1000 * 60 * 10,       // 10m
},
```

- Remove `strategies: [{ name: 'clerk', ... }]` and the `authenticateWithClerk` import.
- Remove `import { authenticateWithClerk } from '../../access/clerk-auth'`.
- Field changes (see §3): drop `clerkId`, `emailVerified`; add `resume` (upload → media, optional) to replace the commented-out `cvUrl`.
- `email` is provided by Payload's auth automatically — **remove the explicit `email` field** from `fields` (Payload auth collections manage it; a duplicate `email` field errors). Keep `name`, `image`, `isAdmin`.

### `plugins/index.ts` — wire `payload-totp` (LAST in the array)

```ts
import { payloadTotp } from 'payload-totp'
// ...
export const plugins: Plugin[] = [
  // ...all existing plugins...
  payloadTotp({
    collection: 'users',
    forceSetup: true,
    disableAccessWrapper: true,   // without this the wrapper 403s public `anyone`-read content
    totp: { issuer: 'aolausoro.tech' },
  }),
]
```

Must be last — it wraps every collection/global already registered.

That whole `<Providers>` wrapper is removed in **P3.2**. For P3.1a: if `providers.tsx` fails to compile after the Clerk deletions, apply the **minimal** edit to remove only the Clerk pieces (`ClerkProvider`, `useAuth`, etc.) and leave a `// TODO(P3.2): remove this whole provider tree` comment. Do not refactor the Redux/theme providers here.
- **`app/(protected)/api/upload/{pdf,photos}/route.ts`** and **`components/admin-route-components/actions/*.ts`** also import `@clerk/nextjs` — these are **P3.2 deletions**. P3.1a leaves them; they already don't compile (part of the 154). Just confirm the P3.1a deletions don't *increase* the error count in files P3.2 owns.

### `package.json`

- `dependencies`: remove `@clerk/nextjs`, `svix`. Remove `@clerk/shared` from `pnpm-workspace.yaml` `allowBuilds` (or the `onlyBuiltDependencies` list if §P3.2's pnpm-key fix landed first).

## §3 — Access control + field cleanup

### Access rules (apply verbatim; most are already close)

| Collection | read | create | update | delete | Notes |
|---|---|---|---|---|---|
| `Projects` | `anyone` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | public portfolio content |
| `Posts` | `authenticatedOrPublished` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | draft-enabled |
| `Categories` | `anyone` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | |
| `Wiki` | **`authenticated`** | `authenticated` | `authenticated` | `authenticatedAndAdmin` | **private** — owner-only knowledge base (review decision) |
| `Media` | `anyone` | `authenticated` | self-or-admin | self-or-admin | keep the existing per-user rules |
| `Jobs` | `authenticated` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | **private** — job-application tracker (status: pending/interview/declined) |
| `Issues` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | `authenticatedAndAdmin` | **private** — issue tracker |
| `CVs` | `authenticated` | `authenticated` | `authenticated` | `authenticatedAndAdmin` | **private** — résumé PDFs |
| `Messages` | `authenticatedAndAdmin` | **`anyone`** | `authenticatedAndAdmin` | `authenticatedAndAdmin` | contact-form submissions; keep `create: () => true` |
| `Users` | self-or-admin | **`authenticatedAndAdmin`** | self-or-admin | `authenticatedAndAdmin` | no public signup |

"self-or-admin" pattern (already used in `Users`/`Media`):
`({ req: { user } }) => user?.isAdmin ? true : { id: { equals: user?.id } }`.

Replace the inline `() => true` / `read: () => true` in `Messages` / `Wiki`
with the named helpers for consistency (`Wiki` `read` becomes `authenticated`,
not `anyone`).

After this pass the only `anyone`-readable collections are `Projects`, `Posts`
(published), `Categories`, and `Media` — `access.int.spec.ts` asserts anonymous
reads still succeed for those and are denied for `Jobs`/`Issues`/`Wiki`/`Messages`/`CVs`.

### Field cleanup

| Collection | Change |
|---|---|
| `Users` | drop `email` field (auth provides it), `clerkId`, `emailVerified`. Keep `name`, `image`, `isAdmin`. (CVs are a dedicated collection with a `user` relationship — no field on `Users`.) |
| `Messages` | add `{ name: 'read', type: 'checkbox', defaultValue: false, admin: { position: 'sidebar' } }` — powers the "unread" stat. |
| `Projects` | rename `projectName` → `title`; add `...slugField()`. (Prisma `Project` had `title` + `slug`.) `useAsTitle: 'title'`. |
| `Jobs` | leave field set as-is (`position`, `company`, `jobLocation`, `jobType`, `status`, `user`) — the Prisma `title`/`slug`/`createdBy` were vestigial; reconcile in the P3.1b migration mapping. |
| `Wiki` | swap `editor: lexicalEditor({})` → the shared `defaultLexical` from `@fields/defaultLexical` for consistency. |
| `Issues` | no change. |
| `Media` | no change (S3 move is P3.3). |
| `Posts` | no field change in P3.1a beyond what §1 forces; the block/hero frontend is P3.1b. |

Regenerate `payload-types.ts` after field changes.

## §4 — `beforeDashboard` stat panel

### Files

- **Create** `components/admin/BeforeDashboard/index.tsx` — an async server component:

```tsx
import { getPayload } from 'payload'
import config from '@payload-config'

export async function BeforeDashboard() {
  const payload = await getPayload({ config })
  const [messages, issues, projects, latestPost] = await Promise.all([
    payload.count({ collection: 'messages', where: { read: { equals: false } } }),
    payload.count({ collection: 'issues', where: { status: { not_equals: 'CLOSED' } } }),
    payload.count({ collection: 'projects' }),
    payload.find({ collection: 'posts', limit: 1, sort: '-publishedAt', depth: 0 }),
  ])
  // render 4 cards: messages.totalDocs, issues.totalDocs, projects.totalDocs,
  // latestPost.docs[0]?.title + publishedAt
}
```

Styling: plain Payload admin CSS classes / a small scoped stylesheet. No new deps.

- **Modify** `payload.config.ts` — `admin.components.beforeDashboard: ['/components/admin/BeforeDashboard#BeforeDashboard']`.
- Run `pnpm run generate:importmap` and commit the updated `app/(protected)/admin/importMap.js`.

### Verify

`/admin` root shows the four cards above Payload's default dashboard; numbers
match a manual `payload.count()`.

## §5 — Testing & verification

### Integration tests (`tests/int/`, vitest, real Mongo)

- **`api.int.spec.ts`** — remove `describe.skip` and the `void Promise.resolve(config).catch(...)` swallow line; move the imports back to module top-level (config now loads). Assert `payload.find({ collection: 'users' })` and `payload.find({ collection: 'categories' })` resolve.
- **`access.int.spec.ts`** (new):
  - anonymous `payload.find({ collection: 'messages', overrideAccess: false })` → throws / empty per Payload's forbidden behaviour;
  - anonymous `payload.create({ collection: 'messages', data: {...}, overrideAccess: false })` → succeeds;
  - a non-admin user cannot `payload.delete` another user (`overrideAccess: false`).
- **`auth.int.spec.ts`** (new):
  - `payload.login({ collection: 'users', data: { email, password } })` returns `{ token, user }`;
  - wrong password → throws;
  - 5 failed attempts → account locked (`payload.login` throws `LockedAuth`).

### E2E (`tests/e2e/`, playwright — not run in CI)

- **`tests/helpers/seedUser.ts`** (new — flagged missing by the Phase 2 final review): `export async function seedAdmin(): Promise<{email,password}>` — `getPayload` + `payload.create({ collection: 'users', data: { email, password, name, isAdmin: true } })`; idempotent (delete-then-create or find-first).
- **`tests/e2e/admin.e2e.spec.ts`** (new — also flagged missing): seed an admin, `login()` (existing helper), assert the dashboard + the 4 stat cards render, create a Project via the admin UI, see it in the list view.
- The forced-TOTP flow blocks a plain password login in e2e. **Default:** gate `forceSetup` on `process.env.NODE_ENV !== 'test' && process.env.PLAYWRIGHT !== '1'` (or an explicit `TOTP_FORCE_SETUP` env, defaulting on) so e2e can log in with password alone. The alternative — `seedAdmin` completing TOTP setup via the REST API — is more faithful but brittle; only adopt it if the planning step finds the env guard leaks into a real deploy path.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| `slugField()` signature differs in the installed Payload 3.86 (arg shape, tracking field). | Check `node_modules/payload` types during §1; the int test catches a bad config immediately. |
| Removing the `email` field from `Users` when data exists. | Fresh db — no data. P3.1b's migration writes `email` via the auth API, not as a plain field. |
| `payload-totp` `disableAccessWrapper` still interferes with public reads. | equilibrium runs exactly this config successfully; `access.int.spec.ts` asserts anonymous `Projects`/`Wiki`/`Media` reads still work. |
| Deleting `proxy.ts` removes protection that something depended on. | Verified there is no `middleware.ts`, so `proxy.ts` is inert. Payload `/admin` enforces its own auth. `access.int.spec.ts` + the manual login check confirm. |
| `providers.tsx` Clerk removal cascades into the public site build. | Minimal Clerk-only edit + `TODO(P3.2)`; P3.1a's build gate is "no new failure", and the whole provider tree is P3.2's to delete. |
| `beforeDashboard` server component + `getPayload` inside the admin render is slow / double-inits Payload. | `getPayload` is memoized by Payload; `depth: 0` + `count` are cheap. If it's a problem, use the `payload` instance from admin context instead. |
| tsc count doesn't drop (Clerk errors were already suppressed / not counted). | Acceptable as long as it doesn't *rise*; the real signal is `test:int` green + config loads. Adjust gate 4 to "≤ 154, and 0 new" if needed. |

## Decisions (resolved in review, 2026-09-08)

1. **CV model** — dedicated **`CVs`** upload collection (PDF, `label` + `user`, private), not a field on `Users`. Registered in `payload.config.ts`.
2. **`Jobs` / `Issues` / `Wiki` are all private** (owner-only `read: authenticated`). Only `Projects`, `Posts`, `Categories`, `Media` are publicly readable.
3. **New db name: `portfolio`** — `mongodb+srv://<cluster>/portfolio`.
4. **e2e TOTP** — default to gating `forceSetup` on an env check (`NODE_ENV !== 'test'` / a `TOTP_FORCE_SETUP` flag defaulting on) so Playwright can log in with password alone. Planning confirms the guard can't leak into a deploy path.
